# PRD: 나의 Todo 앱

## 1. 배경과 목표
할 일을 적고, 마감일과 카테고리로 정리하고, 달력으로 한눈에 확인하는 할 일 관리 앱.
v1(Streamlit + SQLite)은 배포 서버에서 모든 방문자가 DB 하나를 함께 써서 **데이터 분리가 안 된다**는 보안 지적을 받았다.
v2는 **로그인과 사용자별 데이터 분리**를 핵심 목표로, 백엔드 API와 Supabase(RLS)로 다시 만든다.

## 2. 대상 사용자
- 자기 할 일 목록이 필요한 개인 사용자 (여러 사람이 같은 주소를 써도 서로의 목록은 보이지 않아야 함)

## 3. 기능 요구사항

### 필수 (CRUD)
| 기능 | 설명 |
|---|---|
| 추가 | 제목(필수), 마감일(선택), 카테고리를 입력해 할 일을 만든다. |
| 조회 | 목록에서 미완료 → 완료 순, 마감일 순으로 본다. |
| 완료 | 체크박스로 완료/미완료를 바꾼다. |
| 삭제 | 삭제 버튼을 누르고 한 번 더 확인한 뒤 지운다. |

### 로그인 (v2 추가)
| 기능 | 설명 |
|---|---|
| 회원가입 / 로그인 / 로그아웃 | 이메일 + 비밀번호(8자 이상). Supabase Auth를 쓴다. |
| 데이터 분리 | 로그인한 사용자는 자기 할 일만 보고·추가하고·고치고·지울 수 있다. |

### 추가 기능
| 기능 | 설명 |
|---|---|
| 마감일 표시 | 오늘 마감은 노란색, 기한이 지난 일은 빨간색으로 표시한다. 날짜는 사용자 컴퓨터 시간 기준이다. |
| 카테고리 | 카테고리마다 고정된 색을 붙이고, 카테고리별로 골라 볼 수 있다. |
| 캘린더 보기 | 월간 달력에 마감일별로 할 일을 보여 준다. 한 칸에 3개까지 보이고 나머지는 "+N개 더"로 표시한다. |
| 구글 캘린더 내보내기 | `.ics` 파일을 받아 구글 캘린더에서 가져온다. |

## 4. 범위 밖 (이번 버전에서 하지 않는 것)
- 알림, 반복 일정, 다른 사람과 목록 공유
- 소셜 로그인(구글 등), 비밀번호 찾기 화면
- 모바일 앱

## 5. 데이터 구조 (`todos` 표, Supabase Postgres)
| 열 | 종류 | 설명 |
|---|---|---|
| id | bigint (자동 증가) | 고유 번호 |
| user_id | uuid (필수) | 주인. `auth.users` 를 가리키고, 사용자가 지워지면 할 일도 지워진다. |
| title | text (필수, 100자 이하) | 할 일 내용 |
| done | boolean | 완료 여부 |
| due_date | date (선택) | 마감일 |
| category | text (기본값 '일반', 20자 이하) | 카테고리 |
| created_at | timestamptz | 만든 시각 |

## 6. 기술 구성
| 구분 | 사용 기술 |
|---|---|
| 화면 | HTML / CSS / JavaScript |
| 백엔드 | Node.js + Express |
| DB · 로그인 | Supabase (Postgres + Auth + RLS) |
| 배포 | Render |

모두 무료 요금제. 화면은 백엔드 `/api` 만 호출하고, Supabase에는 백엔드만 접속한다.

## 7. 비기능 요구사항 (보안과 품질)
- **데이터 분리**: 모든 표에 RLS를 켜고 "본인 행만" 정책을 둔다. 로그인하지 않은 요청(anon)은 표 권한이 없다. 서버도 모든 쿼리에 `user_id` 조건을 붙인다(이중 잠금).
- **키 관리**: Supabase URL과 publishable 키는 서버 환경변수(`.env`, Render 설정)에만 둔다. RLS를 우회하는 secret / service_role 키는 쓰지 않는다. `.env`는 저장소에 올리지 않는다.
- **로그인 유지**: 토큰은 `httpOnly`, `SameSite=Lax`, 배포 시 `Secure` 쿠키에 둔다.
- **입력 검증**: 서버에서 제목·마감일·카테고리·이메일·비밀번호 형식과 길이를 검사하고, DB에도 제약을 둔다.
- **출력**: 사용자 입력은 화면에 글자(textContent)로만 넣고, CSP 헤더로 외부 스크립트 실행을 막는다.
- **무작위 대입 완화**: 로그인/가입은 IP당 1분에 10회로 제한한다.
- **오류 메시지**: DB 내부 오류 내용은 사용자에게 보여 주지 않는다.

## 8. 성공 기준
- 두 계정으로 각각 로그인했을 때 서로의 할 일이 보이지 않고, 남의 할 일 id로 수정·삭제를 시도해도 실패한다.
- 로그인하지 않으면 할 일 API가 401을 돌려준다.
- 할 일 추가부터 완료 처리까지 한 화면에서 끝난다.
- 서버를 껐다 켜도 데이터가 남는다.

## 9. 알려진 한계와 다음 계획
| 한계 | 설명 | 다음 계획 |
|---|---|---|
| 무료 서버 대기 | Render 무료 요금제는 한동안 안 쓰면 잠들어 첫 접속이 느리다. | 필요하면 유료 요금제로 바꾼다. |
| 횟수 제한 | 로그인 시도 제한이 서버 메모리에 있어 서버가 재시작되면 초기화된다. | Supabase 자체 제한과 함께 쓰고, 필요하면 저장소 기반 제한으로 바꾼다. |
| 비밀번호 찾기 | 화면이 없다. | Supabase 비밀번호 재설정 메일을 붙인다. |
